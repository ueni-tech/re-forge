## 自分の契約と比較する観点

### 第3引数 `ballDiameter` を渡す理由

UI ループは **各ボタンの data 属性値** を第3引数に渡す。`state.ballDiameter` は「現在選択中」であり、判定対象の径とは限らない。**ループ変数と state を混同しない**ための API 設計。

### `.some()` の選択

存在判定だけなら `some` が意図が明確。全件集める必要がない。

## 観察ポイント

ボタン1個ごとに「存在するか？」を問う関数は、**UI ループの内側で呼ばれる**典型。O(n×ボタン数) だが SKU 件数は小さいので実務上問題にならない。件数が増えたらインデックス化を検討。
