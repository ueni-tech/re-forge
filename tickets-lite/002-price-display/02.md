# [002/02] セール価格の反映（変更チケット）

**01 が緑になり、3つの問いと AI レビューを終えてから開く。開く前に「触る箇所・行数」の予測を `solution.ts` 末尾のコメントに1行書く。**

## 背景

01 のリリース後、タイムセール中も通常価格で税込計算されてしまい、「画面の打ち消し線価格とカートの金額が違う」と CS に寄せられた。マスタに税抜の `salePrice` 列が追加される。

移行期間中は `salePrice` が未設定の商品が混在する。

## 要求（業務の言葉）

- 「セール価格が入っている商品は、そちらを基準に税込／税抜の表示金額を出してほしい」
- 「セールがまだ入っていない商品は、今まで通り通常価格で出してほしい」
- 「通常価格が不正なときは今まで通りエラー。セール価格だけが負なら、それもエラーにしてほしい」
- 「セール価格が 0 の無料配布は許可してほしい」

## 受け入れ条件

### 01 の受け入れ条件は維持

`01.test.ts` はすべて緑のまま。境界の関数名・引数の並び・結果の形は変わらない。

### 変更点

`Product` に `salePrice?: number` が増える。

| 判定 | セール価格の扱い |
|---|---|
| `invalid`（`price` / `taxRate`） | **01 と同じ**。加えて、`salePrice` が **設定されていて** かつ 0 未満なら `invalid` |
| 表示の基準額 | `salePrice` が **設定されている**（`undefined` でない）なら `salePrice`、そうでなければ `price` |
| `taxDisplay` と端数（切り捨て） | 01 と同じ。基準額が入れ替わるだけ |
| `salePrice: 0` | 基準額 0 として許可（`invalid` にしない） |

- 「設定されている」は `!== undefined`。`null` は来ない前提でよい

## 境界

変更なし。`resolvePriceDisplay(product, context)`。

```ts
type Product = { price: number; salePrice?: number };
```

## 入出力例

| price | salePrice | taxRate | taxDisplay | 期待結果 |
|---|---|---|---|---|
| 1000 | 800 | 0.1 | included | `ok`, amount `880`, taxLabel `included` |
| 1000 | 800 | 0.1 | excluded | `ok`, amount `800`, taxLabel `excluded` |
| 1000 | （未設定） | 0.1 | included | `ok`, amount `1100`（01 と同じ） |
| 1000 | 0 | 0.1 | included | `ok`, amount `0` |
| 1000 | -10 | 0.1 | included | `invalid` |
| -1 | 800 | 0.1 | included | `invalid`（通常価格が不正。セールがあっても救わない） |
| 199 | 150 | 0.1 | included | `ok`, amount `165`（`150 * 1.1 = 165`） |

## やらないこと

- 打ち消し線用に通常価格を結果へ含めない（結果の形は変えない）
- セール期間（開始・終了日時）は見ない（マスタに数値が入っていればセール中とみなす）
- `salePrice` が通常価格より高い場合のチェックはしない
