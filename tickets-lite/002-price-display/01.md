# [002/01] 価格表示の決定

## 背景

商品詳細ページ（PDP）と一覧で、税抜のマスタ価格を「税込表示／税抜表示」のサイト設定に合わせて画面用の金額にしている。計算がテンプレート・jQuery・カートでそれぞれ書かれており、端数処理がずれて CS 問い合わせになっている。

表示金額を決める処理を純関数に切り出す。

## 要求（業務の言葉）

- 「サイトが税込表示なら、税を乗せた金額を出してほしい。税抜表示ならマスタの金額をそのまま出してほしい」
- 「端数は切り捨てで統一してほしい」
- 「ありえない価格や税率が来たら、金額を出さずエラー扱いにしてほしい」

## 受け入れ条件
`resolvePriceDisplay(product, context)` は次の順で判定し、いずれか1つの結果を返す。

| 順 | 条件 | 結果 |
|---|---|---|
| 1 | `product.price` が 0 未満、**または** `context.taxRate` が 0 未満 | `{ status: "invalid" }` |
| 2 | `context.taxDisplay` が `"excluded"` | `{ status: "ok", amount, taxLabel: "excluded" }` |
| 3 | `context.taxDisplay` が `"included"` | `{ status: "ok", amount, taxLabel: "included" }` |

`amount` の決め方:

- `"excluded"` … `product.price` をそのまま使う
- `"included"` … `Math.floor(product.price * (1 + context.taxRate))`
- `price` が 0 のときは `amount` も 0（無料商品として許可）

補足:

- `price` `taxRate` は有限の数値として来る（`NaN` / `Infinity` は考えない）
- 負数以外の「おかしさ」（税率 2 など）は、このチケットでは invalid にしない
- `product` `context` を変更しない。例外を投げない

## 境界

`solution.ts` から `resolvePriceDisplay` を export する。型の名前・定義場所は自由（`solution.ts` 内で定義する）。

```ts
type Product = { price: number };
type PriceContext = { taxRate: number; taxDisplay: "included" | "excluded" };
type PriceDisplayResult =
  | { status: "ok"; amount: number; taxLabel: "included" | "excluded" }
  | { status: "invalid" };

export function resolvePriceDisplay(
  product: Product,
  context: PriceContext,
): PriceDisplayResult;
```

## 入出力例

| product.price | taxRate | taxDisplay | 期待結果 |
|---|---|---|---|
| 1000 | 0.1 | excluded | `ok`, amount `1000`, taxLabel `excluded` |
| 1000 | 0.1 | included | `ok`, amount `1100`, taxLabel `included` |
| 199 | 0.1 | included | `ok`, amount `218`（`199 * 1.1 = 218.9` を切り捨て） |
| 0 | 0.1 | included | `ok`, amount `0`, taxLabel `included` |
| -1 | 0.1 | included | `invalid` |
| 1000 | -0.1 | excluded | `invalid` |

## やらないこと

- 通貨記号・カンマ区切りなどのフォーマット文字列は作らない（数値とラベルだけ）
- 軽減税率・複数税率は扱わない
- セール・会員割引は扱わない（後続チケット）
- API・DB・DOM は考えない

## 実装者が考えること（コードには出ないが、答えを持つこと）

入力の型（`Product` `PriceContext`）はマスタとサイト設定が決めている環境の事実で、あなたが設計するものではない。一方、戻り値の型（`PriceDisplayResult`）は呼び出し側と握った **契約** であって自明ではない。テストを決定的にするため形は固定してあるが、実装する前に次に自分の答えを持つ。

- `invalid` を例外ではなく戻り値にしているのはなぜか。例外にした場合、一覧の jQuery ループはどう変わるか
- `amount` と `taxLabel` を同じオブジェクトに載せているのはなぜか。金額だけ返す関数とラベルだけ返す関数に分けた場合、呼び出し側で何が起きうるか
- この形で困る変更は何か（例: 「税額だけ別表示したい」「端数を切り上げに切り替えたい」と言われたら）
