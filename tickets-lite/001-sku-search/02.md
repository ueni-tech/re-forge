# [001/02] 在庫切れ SKU の扱い（変更チケット）

**01 が緑になり、3つの問いと AI レビューを終えてから開く。開く前に「触る箇所・行数」の予測を `solution.ts` 末尾のコメントに1行書く。**

## 背景

01 のリリース後、在庫切れの SKU が `exact` で返り、カート投入時に「在庫がありません」で弾かれるケースが CS に多数寄せられた。在庫マスタに在庫数 `stock` 列が追加されることになった。

ただし、マスタの更新は倉庫側の作業で **段階的に進む**。移行期間中は `stock` が未設定のレコードが混在する。

## 要求（業務の言葉）

- 「在庫が 0 の SKU は、選んでも出さないでほしい。近い候補としても出さないでほしい」
- 「在庫 0 でもマスタには載っているので、その色や行を『ありえない』扱いにはしないでほしい」
- 「`stock` がまだ入っていないレコードは、今まで通り『ある』ものとして扱ってほしい。倉庫の作業が終わるまでの間だけ」

## 受け入れ条件

### 01 の受け入れ条件は維持

`01.test.ts` はすべて緑のまま。境界の関数名・引数の並び・結果の形は変わらない。

### 変更点

`InventoryItem` に `stock?: number` が増える。

| 判定 | 在庫の扱い |
|---|---|
| `invalid`（色・行の存在確認） | **在庫を見ない**。`stock: 0` のレコードも「登場した」と数える |
| `exact` | 完全一致レコードが `stock: 0` なら exact にせず、候補探索へ進む |
| `candidates` | `stock: 0` のレコードは候補に含めない（順序・最大3件のルールは 01 と同じ） |
| `stock` 未設定（`undefined`） | 在庫ありとみなす |

- `stock` が `0` のときだけ「在庫切れ」。負数や小数は来ない前提でよい

## 境界

変更なし。`findSku(query, inventory)`。

```ts
type InventoryItem = { sku: string; color: string; diameter: number; row: string; stock?: number };
```

## 入出力例

在庫マスタ（01 と同じ7件に `stock` を足したもの）:

| sku | color | diameter | row | stock |
|---|---|---|---|---|
| R6A | red | 6 | row-A | 3 |
| R8A | red | 8 | row-A | **0** |
| R10A | red | 10 | row-A | **0** |
| R12A | red | 12 | row-A | 5 |
| R20A | red | 20 | row-A | （未設定） |
| R10B | red | 10 | row-B | 2 |
| G10A | green | 10 | row-A | 1 |

| query | 期待結果 |
|---|---|
| red / 10 / row-A | `suggestions`, `["R12A", "R6A", "R20A"]`（R10A は在庫0なので exact にしない。R8A も在庫0で除外。差は 2, 4, 10。R20A は未設定＝在庫あり） |
| red / 10 / row-B | `exact`, `R10B` |
| 全レコードが stock 0 のマスタで red / 10 / row-A | `suggestions`, `[]`（invalid ではない） |
| blue / 10 / row-A | `invalid`（01 と同じ） |

## やらないこと

- 在庫数の多寡で候補の順序を変えない（差の小さい順のまま）
- 「在庫切れだった」ことを結果に含めない（結果の形は変えない）
- `stock` の値の検証（負数・小数・文字列）はしない
